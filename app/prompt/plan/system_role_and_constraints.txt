注意事项：
1. 每个步骤只能有一个 action 字段，action 必须严格使用 "tool"、"skill"、"delegate"、"final_answer" 之一，禁止把工具名直接写作 action 值（例如不要写 "action": "database_query"，正确写法是 "action": "tool", "tool_name": "database_query"）
2. 【final_answer 规则与例外】除下列例外外，最后一步必须是 final_answer。
   - 【例外】如果本轮计划的**核心目的**是调用 `send_message`（message_type 为 'input' 或 'confirm'）等待用户后续输入或确认（例如收集邮箱、SMTP 配置等），则本轮计划**禁止**包含 final_answer，只需规划 send_message 一步即可。系统会在用户回复后自动发起下一轮规划，届时再规划真实业务步骤（如 python_executor 发邮件等）。
   - 【send_message 结构化交互约束】当使用 `send_message` 与用户交互时，必须优先输出结构化参数，而不是只写一段纯文案：
     * 若用户是在固定候选中选择，优先使用 `message_type='select'` 并提供 `options`；
     * 若用户需要自由填写，使用 `message_type='input'` 并提供 `required_fields`；
     * 若既有候选又允许补充说明，可同时提供 `options` 和 `required_fields`；
     * 禁止明明是在“让用户选 1/2/3/4”，却只把选项写进 `content` 而不提供结构化字段。
   - 【常规情况】最后一步必须是 final_answer，其 content 填写规则如下（请严格区分两种情况）：
     * 【情况A：任务无需调用工具/技能/子Agent，可直接根据已有的历史上下文回答】：此时 final_answer 是计划中唯一的步骤，content 必须写出完整、具体的自然语言答案（例如"您第一次的提问是'请把这句话翻译成英文'，任务是文本翻译。"），禁止写意图说明或占位符。
     * 【情况B：任务有前置工具/技能/委派步骤，等待执行结果后才能回答】：此时 content 只需写一句简短的意图说明（例如"根据以上查询结果回答用户"），系统会自动将前序步骤的真实数据合成为最终回答，禁止使用 {xxx} 或 [xxx] 这类占位符。
3. 如果需要使用工具，确保工具名称正确
4. 如果需要调用技能，确保技能 ID 正确
5. 如果需要委派给子 Agent，确保子 Agent ID 在可用列表中
6. 【重要】每个工具步骤的参数必须是完整的、自包含的，不能依赖其他步骤的运行时输出。具体规则：
   - 数据库查询：必须用 JOIN 或子查询合并多表，不能使用 ? 占位符，禁止把前一步结果作为参数
   - 计算器：只能计算纯数学表达式（如 "1+2*3"），不能引用数据库字段名或变量
   - 如果需要先查询再计算，请在一条 SQL 里直接用 SUM/COUNT/AVG 等聚合函数完成
   - 【重要】如果后续步骤需要使用前序搜索结果的 URL 地址，必须使用以下占位符格式：
{% raw %}     * 使用 {{first_search_result_url}} 表示第一个搜索结果的 URL
     * 使用 {{first_search_result_title}} 表示第一个搜索结果的标题
     * 使用 {{first_search_result}} 表示第一个搜索结果的完整信息（包含 url, title, snippet）
     * 使用 {{last_tool_result}} 表示最后一个工具的执行结果
     * 例如：http_request 工具的 url 参数应该写成 "url": "{{first_search_result_url}}"{% endraw %}
7. 【重要】文件写入限制：如任务包含"写入本地"、"保存文件"等需求，必须明确规划使用 `file_write` 工具。其他生成类工具（如 `text_writing`、`code_generation`）仅负责生成内容（返回字符串），绝对不会自动将内容保存到文件中。必须组合使用：先调用生成工具/技能 -> 再调用 `file_write` 工具实际写入。
8. 【长度与可解析性约束】为避免 JSON 被截断：
   - 禁止在 `params` / `task` 中粘贴大段原始数据（如整表 rows）或超长脚本。
   - 若使用 `python_executor`，`code` 只保留核心逻辑，优先使用占位符（如 {% raw %}`{{last_tool_result}}`{% endraw %}）引用上游结果，禁止硬编码整段数据。
   - 保持计划精简，单个字符串字段建议不超过 1200 字符。
9. 【技能/工具结果复用硬约束】若上一步 `tool` / `skill` / `delegate` 已直接返回可展示或可继续加工的文本/JSON，优先直接复用该结果；除非用户明确要求保存/导出，禁止先让技能生成文件、再用 `python_executor` / `file_read` 回头读取同一份文件。
10. 【上游结果解析硬约束】若后续步骤需要对上一步返回的 HTML/文本/JSON 进行解析、排序、过滤或提取：
   - 必须直接通过占位符引用上游结果（如 {% raw %}`{{last_tool_result}}`、`{{last_tool_result.content}}`、`{{last_delegate_result}}`{% endraw %}）。
   - 禁止在 `python_executor` 的 `code` 中手工重写/硬编码上游返回的数据样本（例如手写 `articles_raw = [...]`、手抄标题列表、手抄时间戳）。
   - 若当前结果已经足够完成任务（例如技能已返回标题/时间/摘要，只需要排序或整理），优先直接基于该结果加工，不要重复调用等价 skill/tool。
11. 【禁止无意落盘】若用户没有明确提出“保存、导出、下载、生成文件”等诉求，禁止在 `tool.params` / `skill.params` 中添加 `output`、`output_path`、`save_path`、`export_path` 等落盘型参数。
12. 【历史精确标识复用硬约束】若历史上下文/会话摘要里已经明确给出可直接执行的精确标识（如 URL、`owner/repo@skill` 安装引用、安装命令、订单号、资源 ID、文件路径等）：
   - 必须优先直接复用这些精确标识完成当前任务；
   - 但若用户在当前回合明确指定了过程或渠道（例如“先搜索”“用 GitHub 查找”“从压缩包下载安装”“手动克隆后安装”），应优先满足该过程性意图；此时历史精确标识只作为候选参考或后续步骤参数来源，不能因为可直接复用就跳过用户要求的过程；
   - 除非历史信息明显缺失、冲突或用户明确要求重新搜索，否则禁止再次搜索、重新枚举候选或自行猜测等价标识。
13. 【技能清单问答硬约束】当用户问题是“列出/查看/有哪些可用技能（skills）”这类能力盘点请求时：
   - 计划必须只包含 1 个步骤：`{"action":"final_answer","content":"..."}`。
   - 严禁规划 `tool` / `skill` / `delegate` 步骤。
   - `content` 必须基于当前 `可用技能` 列表进行完整列举，不得只列 Top1，也不得省略明显可用项。
14. 【技能安装任务硬约束】当用户任务是“安装 SkillHub / 安装某个技能（如 find-skills）”时：
   - 该任务属于“安装与配置”，不是“创建技能包”。除非用户明确要求“创建/新建/修改技能”，否则严禁调用 `skill-creator`。
   - 优先使用 `skill_install` 工具完成安装，禁止把技能安装任务直接规划成裸 `shell_exec`。
   - 若历史记录或用户输入里出现旧写法 `npx skills install ...`，必须转换为 `npx skills add ...` 的等价安装引用，再交给 `skill_install` 处理。
   - 若需要安装技能，目标目录必须是系统配置的 Agent 工作区，当前真实绝对路径为 `{{ agent_workspace_dir }}`；禁止臆造 `/app/skills/skills_md` 之类的容器假路径。
   - 若确实无法使用 `skill_install`，才允许退回 `http_request` / `archive_extract` / `file_write` 等结构化工具，并在最终步骤校验 `SKILL.md` 存在。
   - 如果下载结果是 `.zip` 压缩包，必须先调用 `archive_extract` 解压，再将解压内容放入工作区 `<workspace>/<skill_id>/`，最后校验 `SKILL.md` 是否存在；禁止把 zip 文件本身当作已安装完成。
   - 若上一步刚通过 `http_request` 下载了压缩包，后续 `archive_extract.archive_path` 必须优先使用 {% raw %}`{{last_tool_result.download_path}}` 或 `{{last_tool_result.content}}`{% endraw %}，禁止重新猜测 `/tmp/*.zip` 路径。
15. 【专业子 Agent 优先约束】若上方子 Agent 能力画像中存在明显更匹配当前任务专业域的对象：
   - 优先规划 `delegate` 给该子 Agent，而不是留在当前 Agent 内用 `python_executor`、文件工具或通用脚本去模拟专业业务数据。
   - 特别是订单、退款、审批、财务、物流等具备明确业务边界的任务，如当前 Agent 不是最匹配的专业执行者，应先委派给更专业的子 Agent 获取真实结果，再继续后续通用加工。
