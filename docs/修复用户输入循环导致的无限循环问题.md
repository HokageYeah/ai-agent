# 修复用户输入循环导致的无限询问问题

## 问题背景

用户想要查询订单并发邮件时，系统触发如下循环：
1. `general_agent` 规划调用 `send_message(input)` 向用户收集 SMTP 配置
2. 用户提交 SMTP 配置
3. `general_agent` 在新一轮规划中生成 `python_executor` 代码
4. [executor.py](file:///Users/yuye/YeahWork/AIAgent%E9%A1%B9%E7%9B%AE/ai-agent/app/tools/builtin/executor.py) 的 [_analyze_code_for_required_info](file:///Users/yuye/YeahWork/AIAgent%E9%A1%B9%E7%9B%AE/ai-agent/app/tools/builtin/executor.py#867-984) 再次检测到 smtplib，又发出 `await_user_input` 事件
5. 用户再次提交，代码执行失败，再次循环

## 根本原因

`PythonExecutorTool._analyze_code_for_required_info` 在执行前做预检查，只要代码含 smtplib 关键字就触发询问。LLM 在新一轮规划时仍生成含占位符的代码，因此每次都触发——即使用户已经提供过配置。

## 解决方案

**核心思路：在任务级别建立用户输入缓存 `user_inputs_cache`。**

- 用户通过 `send_message(input)` 或 `python_executor await_user_input` 提供配置后，将其持久化到 `AgentRunMemory.user_inputs_cache`
- `python_executor` 检测到代码需要 SMTP 配置时，先检查缓存，有缓存则直接注入并跳过询问
- `send_message(input)` 收集到 SMTP/DB 相关参数后自动写入缓存
